# ADR 0003 — T09 accounts + OAuth (OpenIddict 7.8)

Date: 2026-11-13. Status: accepted (T09 PASS, 10/10 tests).

## Stack
ASP.NET Core Identity (password + TOTP authenticator, first complete
path) + OpenIddict 7.8.0 server/validation, SQLite (same WAL store as
the relay journal family, separate database file). Clients are public
(no secret in v1) + PKCE; scopes per docs/04 §4.2.

## Decisions
1. **API surface verified against the real 7.8.0 assemblies**
   (reflection probe in `work/.tmp/apipeek/`), not docs memory.
   Correct names: `AllowDeviceAuthorizationFlow()`,
   `SetEndUserVerificationEndpointUris()`,
   `EnableEndUserVerificationEndpointPassthrough()`,
   `SetUserInfoEndpointUris()`. Rolling refresh tokens are the
   DEFAULT (only `DisableRollingRefreshTokens()` exists).
   `DisableTransportSecurityRequirement()` lives on the AspNetCore
   builder, not the server builder — and is enabled Development-only.
   The device authorization endpoint has NO passthrough (served
   natively by OpenIddict); revocation and userinfo likewise.
2. **Refresh tokens need `offline_access`.** OpenIddict only issues
   a refresh token when the client asks for the standard
   `offline_access` scope. Both clients carry that scope permission;
   tests request it where a refresh token is needed.
3. **Reuse leeway is zero.** OpenIddict's default leeway made reuse
   detection flaky (a fast replay slipped through). v1 sets
   `SetRefreshTokenReuseLeeway(TimeSpan.Zero)`: a presented-twice
   refresh token is a replay, and the whole chain is revoked.
4. **Consent is explicit on every authorize.** No stored-consent
   shortcut in v1; the consent form re-posts the authorize
   parameters as hidden fields (the authorize POST is validated
   from the FORM body, not the query string — first failure mode).
5. **Device-flow scopes are recovered at the token endpoint.**
   The verification request carries no scopes (only the user code),
   and the user code is NOT the token's ReferenceId, so scope
   recovery at verification silently returned empty. The fix:
   `Exchange` looks up the device code's authorization via
   `FindByReferenceIdAsync(device_code)` → authorization → scopes.
   A response that looked scope-less was misread for an hour: the
   body DID contain an access token; my `grep -v eyJ` pipeline hid
   that line and `head` cut the rest. Lesson: never filter test
   output on content lines.
6. **Identity UI needs `_LoginPartial`.** The default layout
   requires the app to supply `Pages/Shared/_LoginPartial.cshtml`;
   without it the login page 500s.
7. **Test DB isolation:** `ConfigureAppConfiguration` overrides did
   NOT take effect under WebApplicationFactory here (the service
   kept the default `relay.db` in the bin dir). Tests replace the
   `DbContextOptions` registration in `ConfigureServices` instead.
8. **Production guard:** Production refuses to start without a
   configured signing certificate PFX; dev certs are never used
   there. HTTPS is mandatory in production (the dev-only transport
   escape hatch is off outside Development).
9. **Scope policy:** OpenIddict emits scopes as one space-separated
   `scope` claim; the `DevicesRead` policy splits on spaces instead
   of exact-matching the claim value.
