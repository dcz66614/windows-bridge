# 工作流 B：文件整理

状态：**NOT_RUN**（需真实 consumer Muse + 真实 Windows）。

## 目标

证明文件 API 的创建、移动、核对闭环在真实桌面上成立，且冲突处理不默默覆盖。

## 前置条件

- 同工作流 A（绑定、在线、解锁、未暂停、用户允许、写租约）。
- 工作流目录为 `bridge-e2e/B/<run-####>/`。

## 步骤（每轮）

1. 生成 3 个虚构文本文件，内容随机、类型各异：
   - `report-<随机>.txt`（工作报告类）
   - `photo-notes-<随机>.txt`（图片说明类）
   - `invoice-<随机>.txt`（账单类）
   各自计算期望 SHA-256，用 `file.write`（`create_only: true`）创建。
2. 按规则移动到子目录（`file.move`）：
   - `report-*.txt` → `docs/`
   - `photo-notes-*.txt` → `images/`
   - `invoice-*.txt` → `finance/`
   子目录用 `file.mkdir` 创建（幂等，父目录一并创建）。
3. 冲突演练：再次尝试把同一文件移到已存在同名文件的目标，期望返回 `already_exists`，原文件内容不变（SHA-256 核对）。
4. 用 `file.list` 核对三个子目录的清单，用 `file.read` 核对每个文件内容 SHA-256。
5. 释放租约，记录本轮证据。

## 通过标准（每轮）

- 3 个文件都在正确子目录，内容 SHA-256 与期望一致。
- 冲突移动被拒绝且原文件未变。
- 全程无人工介入（除本地批准租约外）。

## 证据（每轮记录）

与工作流 A 同表，增加：移动次数、冲突演练结果、目录清单。

## 已知缺口

- `file.move` 不提供删除；整理不涉及删除。
