# 工作流 A：记事本

状态：**NOT_RUN**（需真实 consumer Muse + 真实 Windows）。

## 目标

证明“观察 → 定位 → 输入 → 保存 → 读回核对”的完整闭环在真实桌面上成立，且中文输入可靠。

## 前置条件

- 设备已绑定、在线、已解锁、未暂停；用户已允许本次任务。
- 授权根已设为测试目录的父目录；工作流目录为 `bridge-e2e/A/<run-####>/`。
- 已持有写租约（`desktop.input` 同意会话）。

## 步骤（每轮）

1. 生成随机文件名 `note-<8位随机>.txt` 与随机内容：一段中文（20–60 字）+ 一段英文（20–60 词）+ 一行数字；计算期望 SHA-256。
2. 用 `file.write`（`create_only: true`）在工作流目录创建文件，写入内容。
3. 用文件 API 读回（`file.read`），核对 SHA-256 与期望一致。
4. 在记事本里打开该文件（界面操作）：观察桌面 → 定位记事本 → 打开文件 → 观察确认文件内容显示。
5. 在记事本末尾追加一行随机中文（`input.type_text`），保存（Ctrl+S），观察确认无“未保存”提示。
6. 再次 `file.read`，核对内容 = 原内容 + 追加行（SHA-256）。
7. 释放租约，记录本轮证据。

## 通过标准（每轮）

- 第 3 步与第 6 步的 SHA-256 均与期望一致。
- 第 5 步的追加行出现在磁盘文件里（不是只在屏幕上）。
- 全程无人工介入（除本地批准租约外）。

## 证据（每轮记录）

| 字段 | 内容 |
|---|---|
| run_id | `A-<####>` |
| 文件名/期望 SHA-256 | 如实记录 |
| 动作数 | 命令条数（按 operation 分组） |
| 授权次数 | 租约获取/续租次数 |
| 耗时 | 从拿租约到释放租约 |
| 结果 | PASS / FAIL + 失败原因与定位 |
| 人工介入 | 有/无 + 内容 |

## 失败处理

任一次失败：保留该轮全部证据（命令记录、观察截图、文件内容），定位原因（租约、观察过期、输入丢失、保存未生效等），修复后回归，不删除失败轮次。
